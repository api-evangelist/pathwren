# Identify a crawler from a User-Agent string

## When to use this

You have a User-Agent header out of an access log and need to know what it is before deciding
whether to allow, block or rate-limit it.

## Steps

1. **Fetch the index once.** `GET /data/agents.json` (`listCrawlers`) returns all 56 records in a
   single ~74KB document, including `count` and `generated_at`. The provider asks you to do this
   rather than fetch 56 per-crawler files.
2. **Match on `user_agent_substring`.** Every record carries a substring that reliably identifies
   the crawler in a UA header. Case-insensitive containment is the intended match. If you would
   rather have the pattern pre-built, `GET /data/ua-regex.json` (`getUserAgentRegex`) returns
   pre-escaped regex for the whole list and per category.
3. **Read the answer off the record.** `operator`, `category` (one of `ai-search`, `ai-training`,
   `archive`, `dataset`, `preview`, `search`, `seo`, `tool`, `user-fetch`), `robots_token` — the
   exact `User-agent:` value to use in robots.txt — `respects_robots_txt`
   (`documented` | `by-design-no` | `disputed` | `n-a`), and `cost_of_blocking`.
4. **Pull the full record if you need provenance.** `GET /crawler/{slug}.json` (`getCrawler`)
   returns the same object plus `operator_docs` and `last_reviewed`. A 404 means the slug is
   unknown — enumerate valid slugs from step 1 rather than guessing.

## Rules that matter

- **A user-agent match is a claim, not a proof.** The contract says so on the field itself. Anyone
  can send `GPTBot` in a header. Before you act on the identification, run the
  `verify-crawler-ip` skill against the operator's published ranges.
- **Training crawlers and AI-search crawlers are different bots with different tokens.** Blocking
  them together removes you from AI search citations for nothing. The `category` field is what
  separates them.
- **`cost_of_blocking` is the index's own assessment**, explicitly labelled as such in the schema
  description. `robots_token`, `user_agent_substring` and `operator_docs` are cited to the
  operator's own documentation.

## Conventions and errors

- No authentication. No rate limit. `Access-Control-Allow-Origin: *`.
- Cache on the `ETag` and revalidate with `If-None-Match`; there is no `Last-Modified`, so
  `If-Modified-Since` is ignored. Data changes at most every six hours.
- A 404 on `/crawler/{slug}.json` returns HTML, not JSON — check the status code, do not try to
  parse the body.
