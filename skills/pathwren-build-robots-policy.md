# Build a robots.txt policy

## When to use this

Someone has decided a stance toward AI crawlers — block training, keep search, block everything,
allow everything — and needs the actual `robots.txt` text, with the right tokens.

## Steps

1. **See the stances.** `GET /policy/{policy}.json` (`getPolicy`) returns the reasoning for one
   stance and the crawlers it names. Eight policies existed at the 2026-09-01 build, among them
   `block-ai-training`, `allow-ai-search-only`, `maximum-ai-visibility`,
   `block-every-ai-crawler` and `block-corpus-and-dataset-builders`.
2. **Take the file.** `GET /robots/{policy}.txt` (`getRobotsPolicy`) returns `text/plain` you can
   append straight to `robots.txt`:
   `curl -s https://www.pathwren.workers.dev/robots/block-ai-training.txt >> robots.txt`
3. **Explain what it does before applying it.** The policy JSON names every crawler the block
   covers. Cross-reference each against `GET /data/agents.json` (`listCrawlers`) for its
   `cost_of_blocking` so the person choosing knows what they are giving up.

## Rules that matter

- **The policy files are generated from the same records as the index**, so they never name a
  token that has changed upstream. Regenerate rather than hand-editing a copy you saved.
- **`robots.txt` only stops a client that reads it.** `respects_robots_txt` on each record is the
  field that tells you whether the operator documents obeying it (`documented`), documents not
  obeying it (`by-design-no`), or is `disputed`. For anything not `documented`, a robots rule is
  advisory and you need a network-layer control instead.
- Never invent a token. If a crawler is not in the index, say it is not in the index.

## Conventions and errors

- Unauthenticated GET, no rate limit, CORS open. Responses are `text/plain` for `/robots/*.txt`
  and `application/json` for `/policy/*.json`.
- Re-fetch after a rebuild — check `generated_at` in `GET /status.json` — rather than caching a
  policy block indefinitely.
