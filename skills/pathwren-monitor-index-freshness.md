# Monitor index freshness before regenerating config

## When to use this

Run this on a schedule, and always immediately before regenerating a `robots.txt`, a WAF ruleset
or an allowlist from this data. The contract does not change; the data does.

## Steps

1. **Read the build record.** `GET /status.json` (`getStatus`) returns `generated_at`,
   `checked_at`, `sources_total`, `sources_ok`, `sources_failed`, `unique_ipv4_prefixes`,
   `unique_ipv6_prefixes`, `crawlers_indexed`, `operators_indexed` and `policies`.
2. **Check every source row.** `sources[]` carries `slug`, `operator`, the upstream `url`, `ok`,
   `http_status`, `error`, `fetched_at`, the operator's own `source_created`, `ipv4_count`,
   `ipv6_count`, a `sha256` of the bytes received and `changed_since_last_fetch`.
3. **Decide.** Regenerate only if something moved: any row with
   `changed_since_last_fetch: true`, or a rise in `sources_failed`. At the 2026-09-01 build,
   `sources_ok` was 12 of 12 and nothing had changed since the previous fetch.
4. **Read the narrative.** `GET /feed.json` (`getFeed`) is a JSON Feed 1.1 of dated change
   entries — index rebuilds, IP refreshes and per-policy regenerations. `/feed.xml` is the same in
   RSS.

## Rules that matter

- **A failing source is the dangerous state, not a changed one.** If an operator's endpoint stops
  answering, the mirrored prefixes go stale silently and a verification check starts failing open.
  `sources_failed` and the per-row `error` are the signal.
- **Do not poll faster than the rebuild.** The index rebuilds at most every six hours and
  `/status.json` states exactly when. Revalidate on the `ETag` and accept the 304.
- Freshness is this provider's substitute for a deprecation policy — there is no versioned
  contract to deprecate, so `changed_since_last_fetch` is the change notification.

## Conventions and errors

- Unauthenticated GET, no rate limit, CORS open.
- No `RateLimit-*` or `Retry-After` headers exist; there is nothing to back off from. The only
  real ceiling is the host platform's 100,000 requests a day across the whole site.
